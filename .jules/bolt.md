## 2024-06-25 - Prevent global re-renders on typing indicator updates
**Learning:** In `client/src/components/room/Chat.tsx`, the `Chat` component extracts the entire `participants` array using `useShallow`. However, the `participants` array updates frequently (e.g., when the `latencyMs` property updates due to ping events). The `participants` array in `Chat.tsx` is only used to look up nicknames for typing indicators. Subscribing to the entire `participants` array causes the entire `Chat` component (which is relatively heavy, rendering all messages) to re-render every time *any* property of *any* participant changes.
**Action:** Remove `participants` from the `useShallow` selector in `Chat.tsx`. Extract the typing indicator text (that resolves user IDs to nicknames) into a new component (e.g., `TypingUsersList`) that takes the `typingUsers` set as a prop. Inside this new component, you can subscribe to the store in a way that minimizes re-renders, or just use `useRoomStore.getState().participants` *if* the trace didn't explicitly forbid it inside render. Wait, the trace says: "Zustand Performance Pattern: Never read `useRoomStore.getState()` directly inside the React render phase, as it bypasses React's reactivity and is a strict anti-pattern. To prevent full component re-renders from frequent store updates (like latency pings), extract localized UI (e.g., typing indicators) into separate components that independently subscribe to the store." So we must extract it into a separate component and subscribe appropriately, or better yet, since we only need the nicknames, we can have a selector that returns just the nicknames.
Another trace memory: "Codebase Specific Context: The `participants` array in the global Zustand store updates frequently due to `latencyMs` socket pings. Subscribing to the entire `participants` array or returning objects from it in `useShallow` selectors causes frequent, unnecessary global re-renders. Always extract specific primitives (e.g., `isBuffering`, `allVerified`) or isolate dependent UI (e.g., typing indicators) into separate components to prevent layout thrashing."
So, I will create a new component `TypingUsersText` inside `client/src/components/room/Chat.tsx` that takes `typingUsers` (Set<string>) and extracts the required primitives. Even better, it can subscribe to just the nicknames.

## 2024-06-25 - Prevent global re-renders on typing indicator updates
**Learning:** Subscribing to the entire `participants` array in a global component (like `Chat.tsx`) using `useShallow` causes the component to re-render whenever high-frequency properties (like `latencyMs`) update for any participant.
**Action:** Extract localized UI elements (like typing indicators) into separate sub-components. These sub-components should subscribe to the store using a selector that returns only primitive values (like a comma-separated string of nicknames) to ensure Zustand's strict equality checks prevent unnecessary renders.
