
## 2024-05-18 - Improved Custom Toggle Switches Accessibility
**Learning:** Custom UI toggle switches designed with standard `<button>` tags and `div` elements often lack semantic meaning, causing screen readers to misinterpret their state and function. Standard generic buttons used as toggles fail to communicate their "on/off" or "checked/unchecked" status to assistive technologies.
**Action:** When creating custom toggle switches (like "Lock room" or "Grant Control"), always explicitly set `role="switch"` and use `aria-checked={true/false}`. Pair these with descriptive `aria-label` and `title` attributes. Additionally, always add explicit `:focus-visible` styles (`focus-visible:ring-2`) since custom components usually strip native browser focus outlines, breaking keyboard navigation visibility.
## 2024-02-09 - Accessible Header and Keyboard Navigation
**Learning:** Icon-only SVG components like `GoogleIcon` need `aria-hidden="true"` even if nested within a button, to prevent screen readers from announcing meaningless SVGs. Adding standard role descriptors to list menus (like `role="menuitem"` for profile options) improves screen reader traversal and focus states are much easier to navigate when consistently utilizing the application's existing design token (`focus-visible:ring-teal-500`).
**Action:** Always add `aria-hidden="true"` to raw SVGs acting as icons. Ensure structural interactive elements (menus, dropdowns) have explicit ARIA roles (e.g. `role="menuitem"`, `aria-expanded`). Use `focus-visible` to enhance keyboard navigation clarity in components, strictly adhering to the `teal-500` outline pattern found in `ThemeToggle.tsx`.
