
## 2024-05-18 - Improved Custom Toggle Switches Accessibility
**Learning:** Custom UI toggle switches designed with standard `<button>` tags and `div` elements often lack semantic meaning, causing screen readers to misinterpret their state and function. Standard generic buttons used as toggles fail to communicate their "on/off" or "checked/unchecked" status to assistive technologies.
**Action:** When creating custom toggle switches (like "Lock room" or "Grant Control"), always explicitly set `role="switch"` and use `aria-checked={true/false}`. Pair these with descriptive `aria-label` and `title` attributes. Additionally, always add explicit `:focus-visible` styles (`focus-visible:ring-2`) since custom components usually strip native browser focus outlines, breaking keyboard navigation visibility.
## 2024-05-19 - Accessible Custom Toggle Switches
**Learning:** Custom UI components built from basic HTML elements (like `div` or generic `button`) often lack inherent accessibility features. When creating custom toggle switches in this application's design system using Tailwind and `<button>`, they require explicit `role="switch"`, dynamic `aria-checked` bindings, and `aria-label`/`title` attributes to be usable by screen readers. Furthermore, standard Tailwind hover states do not provide adequate visual feedback for keyboard navigation; explicit `focus-visible` utilities are necessary.
**Action:** Always include complete ARIA attributes (`role`, `aria-checked`, `aria-label`) and explicit keyboard focus styling (`focus-visible:ring-2`) when implementing or reviewing custom interactive elements like toggle switches in the codebase.
